# [프로젝트] 네이버 블로그 소통 자동화 데스크톱 앱 '이웃메이트': Playwright 브라우저 자동화 × 로컬 LLM(Gemma 4)

안녕하세요! 이번 글에서는 제가 기획부터 설계, 개발, UI 디자인까지 혼자 맡아 만든 Windows 데스크톱 애플리케이션 '이웃메이트'의 개발 과정과 기술 구조를 정리해 보려고 합니다.

이웃메이트는 네이버 블로그 운영자가 매일 반복하는 이웃 소통(공감, 댓글, 서로이웃 관리)을 자동화하는 프로그램입니다. 기술적으로는 실제 브라우저를 다루는 웹 자동화, 사용자 PC에서 직접 돌아가는 로컬 LLM, 그리고 상용 배포를 위한 라이선스 서버까지 한 프로젝트 안에 담겨 있어서, 제가 어떤 문제를 어떻게 풀어 왔는지 보여 드리기에 좋은 사례라고 생각합니다.

1. 프로젝트 개요

• 기간: 2026년 8월 ~ 진행 중
• 역할: 기획 · 아키텍처 설계 · 프론트엔드 · 백엔드 · AI 연동 · UI 디자인 1인 개발
• 플랫폼: Windows 데스크톱 (Electron), 로컬 API 서버, 별도 라이선스 서버
• 주요 기술: Node.js, Express, Playwright, llama.cpp(llama-server), Google Gemma 4, Python(QLoRA 학습)
• 규모: JavaScript · Python 약 5만 줄, 자동 테스트 22개 파일

목표는 "설정은 최소로, 동작은 안전하게"였습니다. 사용자는 주제와 댓글 말투만 고르면 되고, 딜레이나 모델 파라미터 같은 기술적인 값은 화면에 드러내지 않고 내부에서 알아서 조정하도록 설계했습니다.

2. 시스템 아키텍처: 4계층 구조

전체 시스템은 역할에 따라 네 계층으로 나눴습니다.

• Desktop Client: Electron이 앱 창을 띄우고, 같은 PC에서 Express 기반 로컬 API 서버와 AI 엔진을 기동합니다. UI는 이 로컬 API와 통신하며 작업 진행률과 실시간 로그를 받아 보여 줍니다.
• Automation Engine: Playwright로 실제 Chrome을 제어해 공감 · 댓글 · 서로이웃 신청 · 이웃 정리 작업을 수행합니다.
• On-device AI: llama.cpp의 llama-server를 백그라운드 프로세스로 띄워, 댓글 생성과 신청자 판별을 사용자 PC 안에서 처리합니다.
• License Server: 회원 인증, 기기 바인딩, 결제 이벤트에 따른 이용 기간 관리를 담당하는 별도 서버입니다.

UI와 자동화 엔진을 HTTP API로 분리해 둔 덕분에, 화면을 크게 개편할 때도 자동화 로직은 건드리지 않고 테스트를 그대로 유지할 수 있었습니다.

3. 브라우저 자동화 엔진: Playwright 세션과 작업 흐름

네이버 블로그는 공식 API로 공감이나 댓글을 남길 수 없기 때문에, 사람이 쓰는 것과 같은 브라우저를 Playwright로 직접 제어하는 방식을 택했습니다.

• 세션 관리: 로그인 쿠키를 저장해 두고 다음 실행 때 복원하며, 세션이 만료되면 로그인 창을 띄워 사용자가 직접 로그인하도록 안내합니다. 비밀번호는 저장하지 않습니다.
• 작업 흐름: 주제 키워드로 글을 찾고 → 본문과 사진 정보를 읽고 → 공감 · AI 댓글 · 서로이웃 신청을 사용자가 고른 조합대로 실행합니다.
• 상태 피드백: 목표 대비 처리 건수와 실시간 작업 로그를 화면에 계속 전달해, 백그라운드에서 무슨 일이 일어나는지 사용자가 항상 알 수 있게 했습니다.
• 중복 방지: 처리한 글과 블로그를 이력으로 저장해 같은 글에 두 번 소통하지 않도록 했고, 이력은 CSV로 내보낼 수 있습니다.

4. 온디바이스 AI: 하드웨어 감지와 로컬 추론

외부 LLM API를 쓰면 댓글 하나하나가 비용이 되고, 사용자 블로그 데이터도 외부로 나갑니다. 그래서 AI를 사용자 PC에서 직접 돌리는 구조로 만들었습니다.

• 하드웨어 감지: nvidia-smi 등으로 GPU와 VRAM 용량을 확인하고, 그 사양에서 무리 없이 돌아가는 모델을 추천합니다.
• 모델 카탈로그: Gemma 4 E2B(경량)부터 E4B, 12B(고성능)까지 GGUF 양자화 모델을 버튼 하나로 내려받아 교체할 수 있습니다.
• 엔진 관리: llama-server 실행 파일과 필요한 DLL을 자동으로 받아 설치하고, 선택한 모델로 프로세스를 띄우고 재시작하는 과정까지 앱이 관리합니다.
• 결과: 댓글 생성에 외부 API 비용이 들지 않고, 글 내용이 사용자 PC 밖으로 나가지 않습니다.

5. AI 댓글 품질 파이프라인: 생성보다 검증

이 프로젝트에서 가장 공을 들인 부분입니다. LLM이 쓴 댓글을 그대로 올리면 "저도 가봤는데요" 같은 지어낸 경험이나 본문과 상관없는 칭찬이 섞이기 쉽습니다. 그래서 생성 단계보다 검증 단계에 더 무게를 뒀습니다.

• 프롬프트 생성: 글 제목, 본문 요약, 사진 설명과 함께 말투 · 길이 · 금지 규칙, 최근에 쓴 댓글 목록을 전달해 반복 표현을 줄입니다.
• 규칙 기반 검증기: 길이, 본문 핵심어 포함 여부, 근거 없는 방문 · 구매 경험, 들은 이야기 형태의 단정, 최근 댓글과의 유사도를 검사해 하나라도 걸리면 게시하지 않습니다.
• 검수와 학습 데이터: 사용자가 댓글을 승인하거나 고쳐서 저장하면, 그 결과를 SFT · DPO 학습 데이터로 내보낼 수 있습니다.
• 모델 실측 비교: 실제 블로그 글 10건에 같은 프롬프트와 검증기를 적용해 모델별 통과율을 비교했습니다. Gemma 4 12B와 E2B는 10건 중 8건이 검증을 통과했습니다.

직접 QLoRA로 학습한 블로그 댓글 전용 LoRA(v2)도 같은 조건으로 측정했는데, 오히려 통과가 5건에 그쳤습니다. 결과를 숨기지 않고 기록해 두고, 운영 기본 모델은 검증 통과율이 높은 모델로 유지하면서 학습 데이터 보강을 다음 과제로 남겼습니다. "학습했으니 더 좋을 것"이라고 가정하지 않고 같은 기준으로 재는 것이 이 프로젝트에서 지킨 원칙입니다.

6. 소통 주제 추천: 블로그 분석 · 트렌드 · 연관 검색

사용자가 가장 자주 막히는 지점은 "무슨 키워드로 소통해야 하지?"였습니다. 그래서 주제를 찾는 기능을 네 가지 방식으로 만들었습니다.

• 맞춤 추천: 사용자 블로그의 최근 글을 읽고 블로그 성격과 어울리는 이웃층, 키워드를 추천
• 실시간 트렌드: 급상승 검색어를 수집해 순위별로 표시
• 인기 주제: 서로이웃 소통이 활발한 8개 분야의 대표 키워드를 카테고리별로 정리
• 연관 검색: 입력한 키워드의 검색 제안어를 모아 한 번에 담기

7. 이웃 새글 댓글과 내 글 대댓글

새 이웃을 찾는 것과 별개로, 이미 맺은 이웃과의 관계를 유지하는 기능도 만들었습니다. 이웃 새 글 목록을 불러와 소통 대기 · 완료 · 제외 상태로 관리하고, 사용자가 고른 글에만 공감과 AI 댓글을 남깁니다. 내 글에 달린 댓글을 골라 대댓글로 답하는 기능도 같은 탭에 넣었습니다.

전체 자동이 아니라 "목록 확인 → 선택 → 실행" 흐름으로 만든 이유는, 오래 알고 지낸 이웃에게는 사용자가 직접 확인하고 소통하고 싶어 하는 경우가 많았기 때문입니다.

8. 이웃 관리 자동화: 받은 신청 AI 선별

매일 쌓이는 서로이웃 신청 중에는 광고 계정이나 매크로로 보낸 신청이 적지 않습니다. 이를 두 단계로 걸러 처리하도록 만들었습니다.

• 1차 규칙 필터: 대출 · 보험 같은 상업성 키워드나 기계적인 기본 신청 문구를 걸러 거절
• 2차 AI 판별: 애매한 신청은 로컬 AI가 신청 메시지와 블로그 정보를 보고 소통 목적인지 판단해 수락
• 보낸 신청 정리: 오래 수락되지 않은 보낸 신청을 찾아 회수해, 신청 대기 한도에 막히지 않도록 관리

네이버의 수락 · 거절 확인 팝업과 브라우저 확인창까지 자동으로 처리하고, 수락 · 거절 결과를 실시간으로 집계해 보여 줍니다.

9. 계정 보호를 우선한 안전 설계

자동화 프로그램은 빠르게 많이 처리하는 것보다 오래 안전하게 쓰는 것이 더 중요하다고 판단했습니다.

• 작업 사이에 무작위 대기 시간을 두고, 일정 횟수마다 휴식하며 진행
• 서로이웃 신청 일일 한도를 화면에 보여 주고, 한도에 도달하면 자동 종료
• 보호조치 안내나 한도 초과 응답이 감지되면 즉시 모든 작업을 중단

10. 상용화 인프라: 라이선스 서버

유료 배포를 전제로, 외부 의존성 없이 가볍게 운영할 수 있는 라이선스 서버도 직접 만들었습니다.

• Node 22의 내장 node:sqlite로 별도 DB 서버 없이 회원 · 이용권 데이터 관리
• PBKDF2 비밀번호 해시와 HMAC-SHA256 서명 토큰으로 인증
• 하드웨어 정보 기반 기기 지문으로 1인 1PC 바인딩, 주기적 하트비트 검증과 일시적인 오프라인 유예
• 결제 웹훅을 받아 이용 기간을 자동으로 연장

11. 회고와 작업 의뢰 안내

이웃메이트를 만들면서 다시 확인한 것은, 자동화 프로그램의 품질은 "얼마나 많이 하느냐"보다 "얼마나 실수하지 않느냐"에서 갈린다는 점이었습니다. 브라우저 자동화는 예외 상황 처리와 안전장치에, AI 기능은 생성 결과를 검증하고 측정하는 구조에 가장 많은 시간을 썼습니다.

게임 클라이언트 개발 16년 경력과 이번 프로젝트 경험을 바탕으로, 아래와 같은 작업을 프리랜서로 맡고 있습니다.

• Playwright 기반 웹 자동화 · 데이터 수집 · 반복 업무 자동화 프로그램
• 로컬 LLM(llama.cpp, Gemma 등)을 활용한 온디바이스 AI 기능 개발과 품질 검증
• Electron · Node.js 기반 Windows 데스크톱 애플리케이션
• 사용자 인증 · 라이선스 · 결제 연동이 필요한 소규모 서비스 백엔드
• Unity · C++ 게임 클라이언트 개발
