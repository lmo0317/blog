# 네이버 블로그 서로이웃 소통 자동화 프로그램 개발기 2편 | AI 댓글·대댓글·이웃 관리 UI 업데이트

안녕하세요. 지난 개발기 이후 이웃메이트 Engage를 실제로 사용하면서 발견한 불편을 중심으로 화면과 동작을 다시 정리했습니다. 이번 업데이트의 기준은 무엇을 하는 화면인지 바로 이해되고, 지금 조회 중인지 대기 중인지, 몇 건이 처리됐는지 한눈에 보여야 한다는 것입니다.

1. 소통 화면은 목표와 진행 상황을 한곳에서 확인합니다

소통 메뉴에서는 주제를 찾고 해당 주제의 새 글을 읽은 뒤 공감·AI 맞춤 댓글·서로이웃 신청을 선택해 진행합니다. 목표 글 수를 300개로 입력하면 탐색 목표는 300개로 유지하고, 서로이웃 신청은 계정 보호를 위해 100명에 도달하면 자동으로 멈춥니다. 화면 오른쪽 진행 패널에서 목표·완료·AI 댓글·서로이웃·성공/실패를 구분하고 하단 콘솔에서 현재 작업과 대기 상태를 확인합니다.

2. 새 글 댓글은 목록 조회를 눌러야 시작됩니다

새 글 댓글과 내 글 대댓글 화면 모두 같은 위치에 목록 조회 버튼을 둡니다. 탭 전환은 화면만 바꾸고 실제 네이버 조회는 버튼을 눌렀을 때만 시작합니다. 조회 전·조회 중·조회 완료 상태를 구분하고, 끝나면 찾은 글 수와 처리 가능한 항목을 목록에 표시합니다.

3. 내 글 대댓글도 같은 조회 방식과 진행 카드를 사용합니다

내 게시글의 댓글을 먼저 조회하고 답글을 달 항목을 선택한 뒤 실행합니다. 이미 처리했거나 네이버 화면에 답글이 보이는 댓글은 다시 표시하지 않습니다. 오른쪽 대댓글 진행 현황 카드에서 처리할 댓글 수, 완료, 실패, 남은 건수와 진행률을 확인합니다.

4. 이웃 관리에서는 받은 요청과 보낸 요청을 분리합니다

AI 자동 선별을 켜면 조건에 맞는 신청만 처리하고, 선별을 모두 끄면 조건 없이 대기 중인 신청을 모두 수락합니다. 목록의 각 항목에는 개별 수락 버튼을 두고 상단에는 선택 항목 일괄 수락을 제공합니다. 활성 그룹을 읽는 스토어 API도 실제 구현과 맞췄습니다.

5. 로컬 AI 모델 상태를 화면에 정확히 표시합니다

Gemma 4 E2B, 학습된 E2B 댓글 모델, Gemma 4 E4B, Gemma 4 12B를 설치 여부와 활성 상태로 구분합니다. 현재 개발 PC에서는 Gemma 4 12B가 활성 모델이고 E4B는 미설치 상태입니다. 78%에서 멈춰 보이던 로딩률은 서버 모델 목록을 검증해 준비 완료를 100%로 전환하고 오류 원인을 표시하도록 바꿨습니다.

6. 댓글 생성 품질은 모델별로 따로 검증했습니다

실제 네이버 글 10개를 기준으로 Gemma 4 E2B, 학습된 Gemma 4 E2B LoRA, Gemma 4 12B, GPT 계열 모델의 댓글을 비교했습니다. 경량 모델은 짧고 안전한 문장을 만들고 12B 모델은 본문 세부 내용을 더 반영하는 경향이 있었습니다. 학습 모델도 모든 주제에서 자동으로 더 좋은 결과를 보장하지 않으므로 모델 선택과 실제 결과를 함께 확인합니다.

마무리하며

소통, 댓글, 이웃 관리, 설정을 상단 메뉴로 분리하고 목록 조회는 명시적으로 누르게 했으며 진행도와 로그는 오른쪽에 모았습니다. 목표 글 수와 서로이웃 신청 한도도 서로 다른 값으로 관리합니다. 로컬 앱 테스트에서는 댓글·대댓글 목록 조회, 진행 카드, 모델 상태 표시와 관련된 전체 50개 테스트가 통과했습니다.
