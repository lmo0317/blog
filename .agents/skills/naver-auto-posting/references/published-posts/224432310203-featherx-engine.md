# [프로젝트] C++ · DirectX로 만든 자체 3D 게임 엔진 'FeatherX': 포스트 이펙트부터 물 렌더링, 지형까지

안녕하세요! 오늘은 제가 C++과 DirectX로 바닥부터 직접 설계하고 구현했던 자체 3D 게임 엔진, 'FeatherX'의 개발 과정과 기술 구조를 10가지 핵심 파트로 나누어 정리해 보려고 합니다.

상용 엔진을 쓰면 버튼 몇 번으로 끝나는 포스트 이펙트, 물 표현, 파티클, 지형 같은 기능들을 셰이더와 버퍼 단위에서 하나씩 직접 만들어 보면서, 렌더링 파이프라인이 실제로 어떻게 돌아가는지 몸으로 익힐 수 있었던 프로젝트입니다. 그래픽스 프로그래밍이나 엔진 구조에 관심 있는 분들께 참고가 되도록 구현 방식 위주로 정리했습니다.

1. 프로젝트 개요: C++ · DirectX 기반 자체 3D 엔진 'FeatherX'

FeatherX는 C++로 작성한 3D 게임 엔진으로, 그래픽은 DirectX, 물리는 NVIDIA PhysX, 맵 제작은 Lua 스크립트를 사용합니다. 엔진의 기능을 검증하기 위해 공을 굴려 START 지점에서 END 지점까지 도착하는 볼 레이싱 데모 게임을 함께 만들었습니다.

데모 게임은 엔진의 거의 모든 기능이 한 화면에 모이도록 구성했습니다. 수면 위에 떠 있는 코스, 공이 지나가며 남기는 궤적, 불꽃 파티클, 화면 전체에 번지는 빛 효과, 상단의 타이머 UI까지 모두 엔진 내부 모듈로 처리됩니다.

• 사용 언어: C++
• 그래픽 라이브러리: DirectX (Vertex / Pixel Shader)
• 물리 엔진: NVIDIA PhysX
• 스크립트: Lua (맵 제작)
• 주요 구현: Export / Import, Effect, Terrain, UI, 물리, 스크립트 연동

2. 3ds Max 익스포터와 XML 임포트 파이프라인

자체 엔진을 만들 때 가장 먼저 부딪히는 문제는 "모델을 어떻게 엔진으로 가져오느냐"입니다. 저는 3ds Max의 MaxScript로 익스포터를 직접 작성해, 모델과 애니메이션 데이터를 XML 파일로 내보내도록 했습니다.

익스포터는 메시의 정점 위치, 인덱스, UV, 노멀과 노드별 애니메이션 키프레임을 XML 구조로 기록합니다. 엔진 쪽에서는 이 XML을 파싱해 정점 버퍼와 인덱스 버퍼를 만들고, 바로 렌더링 가능한 3D 모델 데이터로 복원합니다.

• MaxScript 익스포터: 모델 · 애니메이션을 XML로 Export
• 엔진 임포터: XML을 읽어 3D Model Data로 Import
• 텍스트 포맷의 장점: 출력 결과를 눈으로 확인할 수 있어 좌표계나 UV 뒤집힘 같은 문제를 빠르게 디버깅할 수 있음

3. 포스트 이펙트 파이프라인: 렌더링 이후의 화면 후처리

포스트 이펙트는 렌더링이 끝난 화면에 Vertex Shader와 Pixel Shader로 한 번 더 처리를 가하는 기법입니다. 씬을 곧바로 백버퍼에 그리지 않고 먼저 렌더 타깃 텍스처에 그린 뒤, 그 텍스처를 화면 크기의 사각형(풀스크린 쿼드)에 입혀 셰이더로 가공해서 출력하는 구조로 만들었습니다.

위 이미지의 왼쪽이 후처리 전, 오른쪽이 후처리 후의 같은 장면입니다. 같은 지오메트리라도 빛 처리 하나로 화면의 분위기가 크게 달라지는 것을 확인할 수 있습니다. 이 구조 위에 Star와 Bloom 효과를 패스 단위로 쌓아 올렸습니다.

4. Star & Bloom 이펙트: 빛줄기와 빛 번짐 표현

두 효과 모두 화면에서 밝은 부분만 먼저 추출하는 데서 시작합니다. 추출한 밝은 영역을 어떤 방향으로, 어떻게 흐리게 하느냐에 따라 결과가 달라집니다.

• Star Effect: 빛을 6방향으로 늘린 이미지를 각각 만든 뒤 하나로 합성합니다. 카메라 렌즈에서 보이는 빛의 회절, 즉 광원에서 뻗어 나가는 빛줄기를 표현합니다.
• Bloom Effect: 추출한 밝은 부분을 가로 방향과 세로 방향으로 나누어 흐리게 한 뒤 원래 이미지에 더합니다. 밝은 물체 주변으로 빛이 은은하게 번지는 효과가 만들어집니다.

블러를 가로와 세로 두 번으로 나누는 이유는 성능 때문입니다. 2차원 블러를 한 번에 처리하면 픽셀마다 샘플 수가 제곱으로 늘어나지만, 방향을 분리하면 같은 결과를 훨씬 적은 연산으로 얻을 수 있습니다.

5. Water 렌더링: 물결과 반사 효과

데모 게임의 코스는 넓은 수면 위에 떠 있습니다. 수면은 하나의 평면(Plane) 메시에 물결과 반사 효과를 더해서 표현했습니다.

시간에 따라 텍스처 좌표를 흘려 수면이 계속 출렁이는 느낌을 주고, 주변 풍경이 비치는 반사 색을 수면 색과 섞어 물처럼 보이게 만들었습니다. 평면 하나로 시작했기 때문에 비용은 거의 들지 않으면서도, 화면의 대부분을 차지하는 배경의 완성도를 크게 끌어올릴 수 있었습니다.

6. 노멀맵 물결과 스카이박스 반사

평면만으로는 수면이 너무 매끈해 보여서, 두 단계로 디테일을 더했습니다.

• Normal Map + Vertex Shader: 노멀맵으로 픽셀 단위의 잔물결 굴곡을 만들고, Vertex Shader에서 정점 단위의 물결을 계산했습니다. 같은 평면이라도 빛을 받는 방향이 픽셀마다 달라져 입체적인 물결이 생깁니다.
• Sky Box 반사: 하늘을 그리는 스카이박스를 Water Plane에 렌더링해서, 물 위에 하늘이 비치는 듯한 효과를 구현했습니다.

이미지의 위쪽은 기본 수면에 노멀맵을 더한 결과, 아래쪽은 여기에 스카이박스 반사까지 합친 결과입니다. 노멀맵이 반사 이미지를 미세하게 일그러뜨리면서 실제 물에 하늘이 비친 것처럼 자연스러워집니다.

7. Tail 궤적 효과: 움직임을 따라가는 꼬리

공이 굴러갈 때 뒤에 남는 빛의 꼬리는 Tail 효과로 만들었습니다. 모델이 일정 거리만큼 움직일 때마다 새 정점을 생성해 꼬리를 늘리고, 일정 시간이 지난 정점은 제거해서 꼬리의 길이를 결정합니다.

생성된 정점들을 이어서 리본 형태로 렌더링하기 때문에, 모델이 움직인 궤도를 그대로 따라다니는 꼬리가 됩니다. 공이 점프하거나 방향을 틀 때 그 궤적이 곡선으로 남아서 속도감과 움직임을 한눈에 보여줍니다.

8. 파티클 시스템: 불꽃과 빛 연출

파티클 시스템은 수많은 작은 입자의 위치, 크기, 회전, 색을 시간에 따라 바꾸면서 불꽃이나 빛 같은 효과를 만드는 기능입니다.

• 입자마다 수명을 두고, 수명이 흐르는 동안 크기와 색을 변화시켜 타오르다 사라지는 불꽃을 표현
• 각 입자는 항상 카메라를 향하는 사각형으로 그려서 적은 비용으로 많은 입자를 처리
• 겹칠수록 밝아지는 블렌딩으로 빛 덩어리처럼 보이게 연출

이미지처럼 공이 특정 지점을 지날 때 붉은 불꽃이나 푸른 빛 파티클이 터지도록 해서, 코스 위의 이벤트를 시각적으로 강조했습니다.

9. Height Map 기반 지형 생성

배경의 산과 언덕은 Height Map 텍스처로 만들었습니다. 높이맵은 픽셀마다 0부터 255까지의 회색값으로 이루어져 있고, 이 값을 그대로 지형의 높이로 사용합니다.

먼저 평평한 격자 메시를 만든 뒤, 각 정점에 대응하는 높이맵 픽셀의 밝기를 읽어 높이를 바꿉니다. 이미지의 왼쪽이 평평한 지형, 가운데가 높이맵, 오른쪽이 높이맵을 적용한 결과입니다. 그림 한 장만 바꾸면 지형 전체를 다시 디자인할 수 있어서, 맵 제작 속도가 크게 빨라졌습니다.

10. 엔진 아키텍처와 개발 회고

최종적으로 FeatherX는 C++ 엔진 코어 위에 렌더러, 포스트 이펙트, 물, 이펙트, 지형, UI, 물리, 스크립트, 에셋 파이프라인이 모듈로 올라가는 구조가 되었습니다. UI는 2D 스프라이트 렌더링과 버튼 이벤트 핸들링을 지원하고, 물리는 NVIDIA PhysX 라이브러리로, 맵 구성은 Lua 스크립트로 처리합니다.

엔진을 직접 만들어 보면서 얻은 가장 큰 배움은, 상용 엔진의 기능 하나하나가 결국 렌더 타깃, 셰이더, 정점 버퍼 같은 기본 요소의 조합이라는 점이었습니다. 포스트 이펙트 한 줄, 물 표면 하나를 만들기 위해 거치는 단계를 직접 구현해 본 경험은 이후 Unity 같은 상용 엔진을 다룰 때도 내부에서 무슨 일이 일어나는지 이해하는 바탕이 되었습니다.
